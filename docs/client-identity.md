# Client Identity (M1)

M1 extends the M0 random 256-bit bearer mechanism to N clients. No new crypto.

Rejected for M1-local: asymmetric client keys, mTLS, OAuth. Complexity unjustified on loopback.

## Data model

- `ClientIdentity { client_id }`: stable string (e.g. `opencode`). Identity never changes across rotation.
- `principal_kind = agent | approver` on every client record (default `agent`).
  Structural separation, not configuration-only: agent principals are
  rejected by approval-review endpoints even if configuration accidentally
  grants `approval.review`; approver principals cannot invoke
  computer-control operations even if granted control capabilities. The
  capability check still applies on top, but self-approval must not depend
  on getting the config right.
- `ClientCredential { credential_id, token_hash (SHA-256, NEVER plaintext), created_at, revoked }`.
- `CapabilityGrant { client_id -> exact capability set }`: same namespace and no-inheritance rules as M0. `approval.review` is an exact-match capability like the others; the principal check runs first.

## Enrollment, storage, rotation, revocation

- Credentials generated by OpenRDC (CSPRNG), never chosen by agents.
- Storage: config dir `clients/<client_id>.json`, mode 0600. File holds ONLY the hash + grants. Plaintext shown once at enrollment.
- Rotation: enroll new credential under the same `client_id`; old hash invalidated.
- Revocation: mark `revoked` (checked on every request) or delete the file. Restart-required in M1.

## Remote-migration safety

Internal model separates stable `client_id` from credential material:

```rust
enum CredentialKind { BearerHash, /* reserved: */ MtlsFingerprint, OAuthSubject }
```

Grants and audit shapes key on `client_id` and never change. Bearer stays valid for loopback; remote (M1.x/M2) adds an outer authenticated-encrypted channel mapped to the same `client_id`.

## Gateway binding

One client credential per gateway process (env/flag), verified at startup like capabilities fail-closed. Honest limitation: MCP stdio cannot distinguish upstream agents, so true per-agent identity arrives with Streamable HTTP auth (M1.x). First slice: one identity per gateway instance (e.g. `opencode`). Gateway can never elevate: it only presents its own credential; host is authoritative for grants.

## M0 migration

Legacy single-token file auto-imported once as client `local-default`. Documented and logged at startup.

## Audit

Every record gains `client_id`. Never log credential material (no plaintext, no hashes).
